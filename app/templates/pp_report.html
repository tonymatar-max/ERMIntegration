Total Revenue defaults to the project's SAP Order amount (same figure as the Dashboard's "Order amount" column) and accepts a plain number or a "+"-separated sum (e.g. 19500+4900). Risk defaults to the value from Redmine but can be overridden here — this override is local to the PP Report only and does not write back to Redmine. Spent is cumulative hours logged through the last day of {{ month }}. "Prev. Accumulated" comes from last month's locked figures — lock {{ prev_month }} first if it isn't already, otherwise it reads as 0. Sales/Cost/Profitability columns use the Daily Rate configured for the project's country, falling back to this month's Daily Rate above if the country isn't set up there. Project Completion is normally computed automatically — click its ⚙/✎ toggle to switch a row to manual and type a percentage (switching back to ⚙ discards it). A row switched to manual with nothing typed yet fills in last month's value as a starting point. Notes always carry forward from {{ prev_month }} once it's locked; Project Completion only carries forward if it was a manual override there — a computed value keeps recomputing fresh each month. Edits to Risk/Total Revenue/Project Completion/Notes are not saved automatically while you're working — click Save draft to keep them without locking. Locking a month also saves whatever's currently on screen first, so it's safe to edit and lock in one go; it then permanently commits those figures. If the month is later reopened, your Risk/Total Revenue/Notes/Project Completion come back exactly as they were (no retyping) while every computed figure recalculates fresh from Redmine's current data. Months must be locked and reopened strictly in order (oldest first when locking, newest first when reopening) — skipping a month would leave the next one's "Prev. Accumulated" reading 0, wrongly showing its whole Accumulated as this month's Amount to Take.
